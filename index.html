手动刷新口令是有后果的操作。 刷新后你会得到一把全新的、与旧口令毫无关系的口令：
· 新上传的文件用新口令加密；
· 老文件仍能打开——旧口令会保留在登记表中，页面按上传时的轮次自动取回；
· 但如果你清了浏览器数据或换了设备且登不上原账号，旧口令就再也算不回来，那些文件等同于报废。

它是怎么存的？

1. 你的文件在浏览器里用口令做 AES-GCM 加密，分块处理，每块带独立的随机 nonce 和块序号校验。

2. 密文写进一个公开仓库的暂存区。公开也没关系——那里从头到尾只有密文。

3. 页面敲一下 GitHub Actions，它把密文从暂存区搬进私有存储库，然后清掉暂存区。

4. 私有库的地址和那枚高权限令牌只存在于 Actions 的 Secrets 里。这个页面的任何一行代码都不知道它们。

已知代价：GitHub 单文件上限 100MB，仓库总量建议控制在 1GB 以内；更大的文件会自动改走 Release 资产通道（单文件 2GB）。上传下载都要等 Actions 跑一趟，通常几十秒。
