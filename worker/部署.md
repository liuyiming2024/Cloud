# 后端部署（Cloudflare Worker）

配好之后，游客打开页面什么都不用填。令牌在 Worker 里，浏览器拿不到也不需要。

## 三步

1. 打开 https://dash.cloudflare.com → **Workers & Pages** → **Create** → **Create Worker** → 起名 `cloud-drive` → **Deploy**
2. 点 **Edit code**，把 `drive.js` 的内容整个粘进去（覆盖原来的），点 **Deploy**
3. 回到 Worker → **Settings** → **Variables and Secrets** → **Add**，加四条（Secret 的勾 Encrypt）：

   | 名字 | 值 | 类型 |
   |---|---|---|
   | `DRIVE_PAT` | 能读写私有存储库的令牌 | Secret |
   | `DRIVE_REPO` | `liuyiming2024/Cloud_file` | Text |
   | `SB_URL` | `https://pimryrsxkwyafmponegp.supabase.co` | Text |
   | `SB_KEY` | Supabase 的 publishable key | Text |

4. 把 Worker 的地址（形如 `https://cloud-drive.xxx.workers.dev`）填进 `js/config.js` 的 `worker: ''`，然后推送页面。

## 配额

- **站长不限**：靠库里的 `role = 'owner'` 认，由服务端从会话推导，伪造不了。
  不用配任何 uid —— 配了反而会漂移。
- **其他人**：单文件 100MB、总共 1GB（按人算，不按全站算）。

要改数字，编辑 `worker/drive.js` 顶部那两个常量。


### 一个前提（重要）

Worker 用 `whoami()` 解析身份，只带 apikey（匿名身份）。

Chat 库在 V-03 把 blanket grant 收窄成了逐函数白名单，
`auth_uid()` / `auth_role()` 已被显式 `revoke ... from public` ——
**不要改用它们**，否则所有登录用户会被降级成访客：
既受 100MB/1GB 配额，又因"无身份只能进 anon- 空间"连自己的空间都进不去。

`whoami()` 在白名单里，一次返回 id / role，正是需要的。

若以后 Chat 再收窄授权，务必确认 `whoami()` 仍在白名单：

```sql
select proname from pg_proc p join pg_namespace n on n.oid=p.pronamespace
where n.nspname='public'
  and has_function_privilege('anon', p.oid, 'EXECUTE')
  and proname='whoami';
```

仓库里有条测试盯着这件事（需要本地一份 Chat 的 schema.sql）：

```bash
node tests/identity-rpc.test.js . /path/to/chat/supabase/schema.sql
```


## 完之后

页面上的令牌框会自动收起来。游客打开就能传，不需要任何令牌。

## 注意

- 免费版每天 10 万次请求，单请求 CPU 10ms。传大文件（>20MB）走 Release 通道，不占 Worker 内存。
- 删除只认归属：oid 对不上就拒绝。Worker 不知道"谁是站长"，所以一视同仁。
